# 稳定性与错误

Agent 项目不是只调用一次大模型，而是一条由模型、工具、数据和程序共同组成的执行链路。稳定性设计的目标，是让每一层只处理自己最了解的问题，并把无法处理的问题交给更上层兜底。

## 目录稳定性

```text
skills/    稳定模型行为
llm/       稳定模型连接
mcp/       稳定工具协议
tools/     稳定真实执行
resources/ 稳定信息来源
utils/     稳定代码复用
agent.js   稳定整体流程
```

`skills/` 约束模型角色、流程和输出格式。`llm/` 封装模型连接、流式响应、重试和超时。`mcp/` 约束工具名、参数和返回格式。`tools/` 执行真实动作。`resources/` 提供固定资料。`utils/` 放内部复用函数。`agent.js` 控制主循环和兜底逻辑。

## 分层错误捕获

```text
Agent 项目要在每一层捕获本层错误；
tools 捕获执行错误，mcp 捕获调用错误，LLM Client 捕获模型连接错误，agent.js 做最终兜底和流程控制。
```

## 错误类型分工

```text
agent.js
- 最大循环次数超限
- 模型连续输出无效结果
- 工具调用后无法继续推进
- 未被其它层处理的兜底异常
```

```text
llm/
- API Key 错误
- baseURL 或模型名配置错误
- 网络超时
- 模型服务限流
- stream 中断
- 模型接口返回格式异常
```

```text
mcp/
- 工具名不存在
- 参数缺失
- 参数类型不正确
- 参数不符合 schema
- 当前 Agent 没有权限调用该工具
- 工具返回值格式不符合约定
```

```text
tools/
- 外部接口超时
- 外部接口返回 4xx / 5xx
- 数据库连接失败
- 文件不存在
- 资源读取失败
- 第三方服务返回异常数据
```

```text
resources/
- 资源文件不存在
- 资源格式错误
- 资源内容为空
- 资源路径配置错误
```

```text
utils/
- 数据格式转换失败
- JSON 解析失败
- 时间格式处理失败
- 参数清洗失败
- 通用校验失败
```

原则是：

```text
谁最了解这个错误，谁先捕获它；
谁能决定流程是否继续，谁再处理它；
最后由 agent.js 兜底。
```
