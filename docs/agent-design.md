# Agent 设计

Agent 项目拆开看，本质上是一些常见工程能力的重新组合：

```text
请求接口
函数传参
JSON 解析
目录分层
错误处理
状态控制
配置管理
```

它看起来复杂，是因为中间多了一个“不稳定但很强”的环节：大模型。

## 最小闭环

Agent 项目的实践可以从一个最小闭环开始：

```text
用户输入一句话
  ↓
模型判断是否需要工具
  ↓
程序解析 tool call
  ↓
调用本地 tool
  ↓
把结果回填给模型
  ↓
输出最终答案
```

这个闭环跑通后，就已经覆盖了 Agent 的核心工作方式。RAG、MCP、多 Agent、权限、日志等能力，都是在这个基础上继续增加工程化能力。

## Node 后端类比

从前端和 Node 后端开发的角度看，可以先这样建立直觉：

```text
agent.js   = 后端入口
llm/       = 封装请求大模型的 service
tools/     = 封装业务接口调用的 service
resources/ = 本地数据
mcp/       = controller/router，负责把模型请求分发到工具
skills/    = prompt 配置
utils/     = 公共函数
```

这个类比不是严格等价，但有助于理解各目录的职责。

## 0-1 设计要点

0-1 设计 Agent 项目时，先明确边界，再设计目录。

需要考虑：

```text
任务边界：服务谁、解决什么问题、输入输出是什么、哪些任务不做。
模型职责：理解意图、拆解任务、选择工具、总结结果、生成回答。
程序职责：调用模型、校验参数、执行工具、处理错误、控制权限和成本。
工具设计：每个 tool 做一件清晰的事，有明确输入、输出和失败结构。
Prompt / Skill：定义角色、流程、工具规则、禁止事项和失败回答。
上下文来源：静态数据放 resources/，动态数据通过 tools 查询，大量文档走 RAG。
主流程：接收输入、调用模型、处理 tool call、回填结果、直到 final 或停止条件。
错误处理：每层捕获本层错误，agent.js 做最终兜底。
安全权限：只读/可写工具分离，高风险操作需要确认。
工程交付：目录、环境变量、日志、测试、README、启动命令、部署方式。
```

一句话概括：

```text
0-1 设计 Agent 项目，本质是在设计“模型、程序、工具、数据、错误、权限”之间的边界。
```
